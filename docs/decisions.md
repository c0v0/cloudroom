# 决策记录（ADR）

> 规则：对外接口（HTTP API / WebSocket 事件 / 配置键 / 发布产物结构 / 数据模型）的任何变化，
> 必须先在这里补一条，并写清回退方式。破坏性变更同时更新 `docs/api.md` / `docs/configuration.md`，
> 并在提交信息里写明影响面。

## 模板

```markdown
## ADR-NNN <标题>（YYYY-MM-DD）

- 状态：提议 / 已采纳 / 已废弃
- 背景：为什么要改
- 决策：改成什么（含接口/配置/输出层面的精确描述）
- 对外影响：调用方/部署方需要做什么
- 回退方式：怎么退回旧行为（命令或配置）
- 证据：验证命令 + 实际输出
```

## ADR-001 对外变化必须留决策记录与回退路径（2026-10-19）

- 状态：已采纳
- 背景：此前接口与配置变化只体现在提交信息和代码里，回退路径靠记忆，部署方难以判断影响面。
- 决策：任何对外可见变化（API 路径/字段、WS 事件、配置键默认值、发布产物结构与文件名）：
  1) 先在本文件补一条 ADR；2) 必须写明回退方式（旧配置/旧二进制/开关/数据迁移的反向步骤）；
  3) 破坏性变更（删字段、改语义、改默认值）视为“需人工复核发布”的变更。
- 对外影响：无运行时影响；调用方获得可追溯的变更清单。
- 回退方式：流程不适用时可修改本文件；无代码回退。
- 证据：`git log --oneline docs/decisions.md`（本文件随仓库版本推进）

## ADR-002 验收基线：`scripts/check.sh` 是唯一验收入口（2026-10-19）

- 状态：已采纳
- 背景：构建/检查/测试命令分散在 backend、frontend、frontend-server、test-server 四处，新人需要读多个文档才能判断“能不能过”。
- 决策：所有门禁统一收敛到 `scripts/check.sh`（密钥扫描 + Rust fmt/clippy/构建/测试 + 前端类型检查/构建 + 端到端集成 + 依赖漏洞/许可 + 锁文件哈希）；新增门禁必须同时回填到该脚本与 README 的“一条命令验收”。缺工具时默认 SKIP 并打印安装提示，`--strict` 下 SKIP 视为失败。
- 对外影响：新增 `scripts/` 目录与 `.githooks/`；无运行时行为变化。
- 回退方式：删除 `scripts/check.sh` 及 README 对应小节即可，不影响业务代码与部署产物。
- 证据：`./scripts/check.sh` 输出（见 `docs/plans/2026-10-19-工程底座与可维护性.md`）

## ADR-003 后端代码按接口/应用/领域/基础设施组织（2026-10-19）

- 状态：已采纳
- 背景：后端原先为单层 `src/*.rs`，HTTP 处理器、业务用例、SQLite 仓储和外部适配器混放在一起，跨模块依赖只能靠阅读确认。
- 决策：`backend/src/` 分为 `api/`（接口层）、`app/`（应用层）、`domain/`（领域层）、`infra/`（基础设施层）；`config`、`error`、`util` 作为共享基础。依赖方向固定为 `api → app → domain`、`api/app → infra`、`infra → domain`。仅移动/改名/拆分/合并，不改变 HTTP/WS 契约与运行时行为。
- 对外影响：无。HTTP API、WebSocket 事件、配置键、数据库结构与发布产物均不变。
- 回退方式：按提交逆序回退本次分层改动即可恢复原目录结构；无数据或配置迁移。
- 证据：见 `docs/plans/2026-10-19-代码分层整理.md`（静态路径检查；按要求未编译、未测试）。

## ADR-004 邀请撤销的终态语义（2026-10-21）

- 状态：已采纳
- 背景：`revoke_invite` 对已消费/已过期邀请返回 200，但仓储层实际不更新（`consumed_at IS NULL`），管理端可能误判撤销成功。
- 决策：邀请撤销按服务端状态返回固定结果，响应结构保持 `{"ok":true}` 或现有错误结构不变：
  - 未使用且未过期、未撤销的邀请：200，执行撤销。
  - 已撤销但未使用、未过期的邀请：200，幂等成功。
  - 已使用邀请：409 `conflict`，不修改记录。
  - 已过期邀请：409 `conflict`，不修改记录。
  - 不存在或类型/房间不匹配：404。
- 对外影响：调用方对已使用/已过期邀请不能再把 200 当作撤销成功；需要按 409 处理并刷新列表。前端当前仅在 `active` 邀请上显示撤销按钮，已有错误提示可显示 409 消息；无新增字段。
- 回退方式：回退本次实现提交，恢复旧行为（已使用/已过期撤销返回 200 no-op）。无数据或 schema 迁移。
- 证据：`cargo test --test e2e room_mutes_and_invite_revoke_paths admin_invite_revoke_and_audit` → 2 passed；`scripts/check.sh` → 16 PASS / 0 FAIL / 2 SKIP；完整后端测试 12 unit + 21 e2e passed。
